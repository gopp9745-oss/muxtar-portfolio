# MUXTAR — 3D Portfolio

Адаптивное портфолио 3D-художника с React, TypeScript, Supabase и Netlify. Публичный сайт показывает только опубликованные проекты. Административная панель находится по адресу `/admin/login`.

## Требования

- Node.js 20.19+ или 22.12+ и npm.
- Аккаунт Supabase и созданный проект для постоянного хранения, авторизации и загрузки файлов.
- Аккаунт Netlify для публикации (можно использовать другой статический хостинг с SPA fallback).

## Установка и локальный запуск

```bash
npm install
```

Скопируйте `.env.example` в `.env.local` и укажите публичные значения проекта Supabase:

```env
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_OR_PUBLISHABLE_KEY
```

Это публичные клиентские значения, не секреты доступа. Никогда не помещайте `service_role` key в переменные `VITE_*`, репозиторий или браузерный код.

```bash
npm run dev
```

Без настроенных переменных окружения главная страница открывается с пустым состоянием, а CMS показывает, что backend не подключён. Функции записи без Supabase не имитируются.

## Настройка Supabase

1. Создайте проект в Supabase Dashboard.
2. В SQL Editor выполните содержимое `supabase/migrations/0001_portfolio_schema.sql`. Скрипт создаёт таблицы проектов и профиля, RLS-политики, публичные buckets `portfolio-media` и `portfolio-models`, а также лимиты: 12 МБ на изображения и 50 МБ на модель.
3. Создайте владельцу пользователя через **Authentication → Users → Add user** (email/password). Отключите публичную регистрацию в Authentication settings.
4. Назначьте роль администратора из доверенного SQL Editor. Подставьте точный UUID созданного пользователя:

```sql
update auth.users
set raw_app_meta_data = coalesce(raw_app_meta_data, '{}'::jsonb) || '{"role":"admin"}'::jsonb
where id = 'UUID_ПОЛЬЗОВАТЕЛЯ';
```

`app_metadata` нельзя менять из клиентского приложения; права проверяются RLS-политиками таблиц и Storage. После смены роли пользователь должен заново войти, чтобы получить обновлённый JWT.
5. В **Project Settings → API** возьмите Project URL и публичный anon/publishable key, заполните `.env.local` и перезапустите dev-сервер.
6. Добавьте URL локального сайта и production-домен в **Authentication → URL Configuration → Redirect URLs**. Вход паролем не использует OAuth redirect, но точный список origin полезен при дальнейшей настройке Auth.

Публичный Storage предназначен для изображений и моделей, на которые ссылаются опубликованные проекты. Владелец несёт ответственность за загружаемые права на материалы. Удаление записи удаляет её файлы из bucket; при очистке отдельных кадров из редактора также удаляется файл.

## Публикация на Netlify

1. Запушьте репозиторий в Git-провайдер и создайте новый сайт в Netlify, выбрав репозиторий.
2. Netlify использует `netlify.toml`: команда `npm run build`, каталог публикации `dist`, SPA-маршруты перенаправляются на `index.html`.
3. В настройках сайта добавьте `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` в **Environment variables**, затем запустите новый deploy.
4. В Supabase добавьте production-домен в настройки Auth; проверьте публичный просмотр и админ-сценарии после деплоя.
5. Для собственного домена откройте **Domain management → Add a domain** в Netlify, внесите DNS-записи, которые покажет Netlify, и дождитесь выпуска HTTPS-сертификата. Затем настройте этот домен в Supabase Auth.

Публикация не выполняется автоматически этим репозиторием. До указания владельцем Supabase проекта, ключей и домена внешняя база, авторизация, загрузки и публичный deploy не считаются настроенными.

## Управление контентом

- `/admin/login` — вход пользователя, которому владелец назначил `app_metadata.role = admin`.
- Раздел «Проекты» создаёт черновики и публикации, редактирует запись по стабильному UUID, управляет slug, описаниями, категорией, инструментами, годом, обложкой, дополнительными кадрами и моделью.
- Изображения поддерживают JPG, PNG, WEBP, AVIF и GIF до 12 МБ. GLB/glTF — до 50 МБ. Дополнительные кадры можно менять местами.
- Раздел «Профиль сайта» редактирует бренд, слоган, биографию, специализацию, навыки, ПО, интересы, контакты и видимость секций. Неуказанные ссылки не показываются.
- Перед сохранением проверьте, что проект действительно нужно публиковать. Публикации становятся видны публичной галерее автоматически после успешной записи в Supabase.

## Экспорт модели из Blender

1. В Blender откройте сцену и удалите ненужные камеры, источники света и объекты.
2. Оптимизируйте геометрию и текстуры, примените трансформации; для web используйте разумный размер текстур и число полигонов.
3. Выберите нужные объекты и используйте **File → Export → glTF 2.0**.
4. Выберите формат **glTF Binary (.glb)** и включите только требуемые материалы/текстуры.
5. Проверьте размер файла (не более 50 МБ) и загрузите его в редактор проекта. Формат `.blend` браузер не загружает.

Просмотрщик Three.js/R3F открывает модель только на странице проекта, когда указан GLB-файл; вращение поддерживает мышь и касание. Если модель не загрузилась, пользователь увидит ошибку и доступный статичный рендер.

## Архитектура и безопасность

- `src/pages` — публичные страницы и CMS; `src/components` — UI; `src/lib` — запросы к Supabase.
- `supabase/migrations/0001_portfolio_schema.sql` — схема и политики доступа.
- Публичная роль может читать только опубликованные проекты и публичное содержимое профиля. Запись/изменение/удаление и Storage upload ограничены JWT app metadata администратора.
- Административный guard в React нужен для навигации, но защитой служат серверные политики Supabase.
- Для production проверяйте RLS и Storage policies после изменений схемы, используйте уникальные пароли и включите MFA в Supabase для учётной записи владельца.
